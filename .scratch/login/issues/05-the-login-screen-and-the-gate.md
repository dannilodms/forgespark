# 05: The login screen and the gate

**What to build:** A user opens the app, types their e-mail on the login screen, receives a code, types it on the same screen and lands in the app. The gate of the app now leads to the setup, the login or the app; a session that ends mid-work sends the user back to the login with a notice and returns them afterwards; the app speaks the user's preferred language once logged in. The landing after the login is provisional in this ticket: a route at the root with one sentence, which 06 replaces with the shell. Rules: State and Tests in the frontend rules of `CODING_STANDARDS.md`; the Framed pane recipe in `DESIGN.md`. Verifiable in the browser with Mailpit.

**Blocked by:** 04 (Checking the code: the session, who is acting, logging out and the origin).

### Decided while building

- **How a 401 reaches the router.** `request.ts` has no router, and every generated function calls it, so it tells a listener of every 401 (`whenUnauthorized`), and `access` sets the listener in `createApp`, where the router is. A 401 counts as a session that ended only once a screen past the login has opened (`router.state.resolvedLocation` is set and is neither `/login` nor `/setup`): the gate's own read on a page just opened, at the login or after the setup, finds nobody logged in and is no ended session. The listener forgets every query, keeps that nobody is logged in, and navigates to `/login?notice=session_ended&return_to=...` (replace). A screen never handles a 401. The QueryCache `onError` was the other candidate; it would miss requests made outside Query, such as the writes of a TanStack DB collection. Recorded in Data module of `CODING_STANDARDS.md`.
- **Who is logged in is a value, not a failure.** `loggedInUserQuery` resolves with `null` for 401, so the gate decides with it and the error screen is for real failures (a 500 shows it, with the trace identifier).
- **The gate keeps a deep address without a notice.** An address other than the root, the login and the setup, opened with no session, leads to `/login?return_to=...`. A browser whose cookie expired cannot be told from one that never logged in, so no notice is shown; the return makes a bookmark work after the login.
- **"A path of the app"** is a text that starts with one slash and not with `//` or `/\`; anything else leads to the root. A path the app has no route for leads a logged-in user to the root too.
- **The session ending while the person works** is seen by any request; with the landing of this ticket, the read of who is logged in when the person comes back to the tab a minute or more after the last read (TanStack Query's refetch on focus, `staleTime` of one minute). 06 adds the read at an interval.
- **The preferred language** is applied by the gate whenever it knows a user, and the language of the selector, kept apart in `i18n.ts`, whenever it knows nobody: after a logout and after a session that ended. A page loaded again starts in the browser's language and switches as soon as the gate reads the user.
- **The flow does not hold the attempts left.** The spec put them in the step of the code; each wrong code is answered with `attempts_left`, which shows under the field as the answer of the API, so the flow holds only the e-mail and when the code was asked for.
- **The answer under the code field stays when the field is left.** TanStack Form drops an `onSubmit` error when a field is validated for any other cause, blur included; the line under the field then vanished between the press and the release of "Send a new code" or "Log in", moving the button from under the pointer, and the click was lost. The code field passes no `onBlur`, so the answer stays until another code is typed.
- **The wait for a new code** is counted from the moment the API answered the ask, by the clock of the browser; the API counts from its own record of the ask, which is earlier, so the screen never opens the button before the API accepts.
- **The logout of this ticket** is a button on the provisional landing, so the criterion can be tried in the browser; 06 moves it into the user menu.
- **A new code resets the field** and its answer; asking for it past the limit shows the answer above the form and keeps the step.
